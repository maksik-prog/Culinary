СОБСТВЕННАЯ ЗАДАЧА: Транспортная логистика
Тема: Города, маршруты, транспортные средства (оптимизация доставки)

ОПИСАНИЕ ПРЕДМЕТНОЙ ОБЛАСТИ:
Компания занимается грузоперевозками между городами. Необходимо хранить
информацию о городах, доступных маршрутах между ними, а также транспортных
средствах, которые выполняют рейсы. Граф позволяет найти оптимальные пути
доставки, цепочки пересадок и перегрузок груза.

ТАБЛИЦЫ УЗЛОВ (NODE):

1. Cities — города / транспортные узлы
   Атрибуты: city_id, name, country, population, has_warehouse

2. Routes — маршруты (ребро → узел: маршрут как самостоятельная сущность)
   Атрибуты: route_id, code, distance_km, avg_duration_hours, is_active

3. Vehicles — транспортные средства
   Атрибуты: vehicle_id, plate_number, type (Грузовик/Поезд/Самолёт),
             capacity_kg, fuel_type

ТАБЛИЦЫ РЁБЕР (EDGE):

1. Connects — город соединён с городом через маршрут
   (Cities → Cities)
   Атрибуты: distance_km, toll_cost_usd, road_type (Автодорога/ЖД/Авиалиния),
             opened_date

2. Serves  — транспортное средство обслуживает маршрут
   (Vehicles → Routes)
   Атрибуты: assignment_date, trips_per_week, last_maintenance_date

3. Transfers — перегрузка/пересадка в промежуточном городе
   (Cities → Cities)  [другой тип связи, отличный от Connects]
   Атрибуты: transfer_time_hours, transfer_cost_usd, warehouse_required, added_date

ПРИМЕРЫ ДАННЫХ:
  Города: Минск, Брест, Гродно, Витебск, Гомель, Варшава, Вильнюс,
          Киев, Москва, Рига, Берлин, Прага
  Транспорт: 5 грузовиков, 3 поезда, 2 самолёта
  Маршруты: Минск–Брест, Минск–Варшава, Минск–Москва и т.д.

ПРИМЕРЫ ЗАПРОСОВ MATCH (не менее 5):

5.1  Найти все города, в которые можно доехать из Минска напрямую,
     и транспорт, обслуживающий эти маршруты.
     Цепочка 3 узла: Cities → (Connects) → Cities ← (Serves) ← Vehicles

5.2  Найти авиационные маршруты и все самолёты на них.
     Цепочка: Vehicles → (Serves) → Routes ... (join Cities)

5.3  Маршруты через конкретный транзитный город (пример: Брест).
     Цепочка 3 узла: Cities ← (Connects) ← Cities → (Connects) → Cities

5.4  Города, из которых возможна пересадка в Берлин, с указанием стоимости.
     Цепочка: Cities → (Transfers) → Cities → (Transfers) → Cities(='Берлин')

5.5  Транспортные средства, покрывающие маршруты дороже 200 USD пошлиной,
     и конечные города этих маршрутов.
     Цепочка 4 узла: Cities → (Connects) → Cities ← ... ← Vehicles

5.6  Лёгкие маршруты (distance_km < 500) с грузовиками большой грузоподъёмности.

ПРИМЕРЫ SHORTEST_PATH (не менее 2):

6.1  (шаблон "+") Кратчайшие пути из Минска до любого другого города через
     связи Connects. Вывести полный маршрут через STRING_AGG и конечный город
     через LAST_VALUE + LAST_NODE.

6.2  (шаблон "{1,4}") Пути из Варшавы за 1–4 шага через Transfers,
     с выводом всех промежуточных пунктов и суммарной стоимости пересадок.

ОБОСНОВАНИЕ ВЫБОРА ТЕМЫ:
Транспортно-логистическая сеть является классическим графом:
- узлы = города с атрибутами (население, наличие склада)
- рёбра = маршруты с весами (расстояние, стоимость, тип дороги)
- задача SHORTEST_PATH имеет прямое практическое применение для
  нахождения наиболее выгодного или быстрого пути доставки
- задача о заменяемости (аналог CanReplace) — поиск альтернативных
  маршрутов при недоступности основного
